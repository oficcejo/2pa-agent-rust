## 2. 需要处理的代码问题

### P0：静态文件读取可越出目录；交易接口缺少应用层鉴权

- `src/web/static_files.rs:41` 直接把 URL 路径拼到 `static` 下，没有拒绝 `..`、绝对路径或检查规范化后是否仍在目录内。
- 现有 `test_path_traversal_static_files` 本地测试验证了编码路径可以读取项目根目录文件，且把 HTTP 200 当作通过条件。该测试也检查 `.env` 路径返回成功，测试输出未打印文件内容。
- `src/web/server.rs:25` 至 `:32` 暴露分析执行、写配置和撤单接口，路由没有鉴权中间件，CORS 为 permissive。
- `src/web/service.rs:742` 仅以请求的 `execute` 为执行入口，未在该入口再次校验实盘授权标志；自动交易开关本身也不是访问控制。
- 线上只读账户与历史接口可以不带凭据访问。未在线探测敏感文件或写接口；反向代理对写接口是否有额外限制尚未验证。

建议：首先限制敏感接口访问并实现统一鉴权；静态文件采用允许列表或经过目录边界验证的读取；执行入口统一校验权限与运行模式。将穿越测试改成期望拒绝，使用无敏感内容的测试文件。

### P1：AlphaPilot 的置信度字段与执行器不一致，导致信号全部无法开仓

- 生产者 `src/orchestrator/two_stage.rs:223` 写 `confidence`。
- 消费者 `src/okx/trading.rs:575` 只读 `trade_confidence`，缺失按 0 处理。
- 历史列表和交易审计也只读 `trade_confidence`，因此 UI 摘要显示空值。
- 线上 09-09 09:45:04 的决策给出 `confidence=77`，执行返回“交易信心度 0% 低于设定风控门槛 40%”。
- 最近 141 条 AlphaPilot 决策均为市价开仓意图；审计中有 137 条对应的 0% 拒绝，没有 AlphaPilot 成功提交证据。决策与审计条数不同，不能假设每条决策都请求过执行。

建议：统一结构化决策契约，生产者、校验器、执行器和 UI 使用相同字段；在生产者到执行器之间增加契约测试。不要靠降低置信度阈值绕过此错误。

### P1：最小下单量和余额回退可以突破硬风险限制

- `src/okx/trading.rs:524` 将按风险算出的不足最小量的订单向上补到 `minSz`。
- `src/okx/trading.rs:552` 在总可用余额足够时直接返回 `minSz`，没有继续检查保证金比例上限。
- `src/okx/trading.rs:484` 在可用保证金为 0 时，退回使用总权益；冻结或已被占用的资金被重新当作可用。
- 余额读取失败且没有数值时，还会退回默认数量；线上默认数量为 35，跨品种复用该数值尤其容易造成单位混淆。

离线 mock 已复现：

| 情景 | 应有行为 | 当前结果 |
|---|---|---|
| 权益 $100，风险预算 2%，最小一张损失 $50 | 拒绝 | 返回 1 张，风险 $50 |
| 可用 $100，保证金上限 25%，最小一张保证金 $33.33 | 拒绝 | 返回 1 张 |
| 总权益 $100，可用保证金 $0 | 拒绝 | 返回 0.75 张 |

历史 30 次余额不足中，9 次为 `BTC-USDT` 数量 `35.00000000`，21 次为 ETH 永续数量 `0.90`。现货数量是基础币数量，不能把“35 张”的思维直接套到 BTC 现货。当前实现和历史版本差异仍需部署记录核实。

建议：无法满足交易所最小量时拒绝交易，不能放宽硬上限；区分字段缺失、读取失败和合法的 0 余额；实际可用保证金需要考虑已有挂单与账户模式。

### P1：移动止损失败后的回退会撤掉保护，并可能产生反向开仓

- `src/web/service.rs:856` 在修改失败后撤销同品种所有 `conditional` 条件单，未核对归属。
- 随后的重建请求 `:864` 只有止损，未保留原止盈；如果新止损请求失败，旧保护已经被撤销。
- 新请求未设置 net 模式的 `reduceOnly`，也未设置双向模式的 `posSide`。在持仓已被其他事件平掉等情形下，遗留反向条件单可能增加反向风险敞口。
- `src/web/service.rs:949` 的 `MOVE_SL_TP` 分支绕过了单独移动止损分支的“只能收紧止损”检查。
- 读取保护单仅保存遍历中的一个 `algo_id`，没有可靠匹配持仓方向、策略归属，也只查询 `conditional`，可能漏掉 OCO。

建议：以具体保护单及持仓标识执行原子修改；回退要保留保护与止盈、正确设置只减仓及持仓方向；各管理动作共用同一套止损不可放宽检查。以上为代码路径审查，未在实盘触发验证。

### P1：持仓读取失败时继续开仓；双向持仓方向解析错误

- `src/okx/trading.rs:774` 使用 `if let Ok(positions)`，读取失败会跳过持仓互斥检查，继续执行。
- `src/web/service.rs:663` 读取失败时同样保留“无持仓”的初始状态，AI 会获得错误账户上下文。
- `src/web/service.rs:669` 仅用数量正负判断方向。OKX 双向模式的空仓可以是正数量并带 `posSide=short`，此时会被识别为多仓。
- 平仓入口 `:795` 没有传 `posSide`，与支持双向模式的配置不一致。
- `src/okx/trading.rs:805` 撤销普通挂单未过滤 `pa` 客户端前缀，可能影响同品种手工单或其他策略；撤单失败也未阻止继续新下单。

建议：账户状态未知时拒绝新开仓；按真实持仓模式解释 `posSide/pos`；只管理本策略订单；同账户同品种的检查、撤换与提交需串行化，避免并发请求绕过保护。

### P1：120 秒信号限制实际变成 45 分钟；挂单寿命没有独立过期清理

- `src/okx/trading.rs:723` 使用 `max(max_pending_bars × timeframe, max_signal_age_seconds)`。
- 默认 15 分钟周期、3 根 K 线，得到 2700 秒，而不是配置的 120 秒。离线复现中，收盘已过去 180 秒的信号仍进入后续置信度检查。
- `max_pending_bars` 没有独立驱动挂单到期撤销；仅在新开仓提交路径撤旧单。如果后续一直观望，旧入场单可能持续有效。

建议：分别执行“信号新鲜度”和“已提交订单寿命”限制；市价执行前重新核对现价、保护价和费用后的预期收益。

### P2：AlphaPilot 回放不是严格因果；仓位目标没有形成持仓管理闭环

- `src/indicators/alpha_pilot.rs:204` 的 `op_jump` 用整个输入序列计算均值/标准差，然后重新计算全部历史值。
- 复现：向 `[0,0,0,1]` 追加 `100` 后，原第四个 JUMP 值从约 `-0.000003` 变为 `-0.958764`。
- 因此不能把一次性全量计算的历史输出直接当作逐棒可交易信号来回测。当前实时最后一根计算不意味着使用了真实未来数据，但回放与在线结果可能不一致。
- `:392` 只产生 OPEN/WAIT；持仓上下文在编排器中只保存记录，没有参与 AlphaPilot 的平仓、反向或减仓决策。中性目标不自动平仓，反向目标可能仅被已有持仓保护拦截。
- 连续 `target_position` 没有传入实际算量；`confidence` 是目标仓位幅度，`estimated_win_rate=60` 是写死常数，并非经历史成交校准的胜率。
- 因子明确包含 `-SUPERTREND_DIR`，本身有逆趋势特征。不能因为名称含 SuperTrend，就把目标方向当作可靠的顺趋势方向。自适应策略把其方向当作硬门禁前需要独立验证。

建议：使用逐时点统计或严格逐前缀重放验证因果性；定义目标仓位到实际持仓的完整状态转换；区分信号强度与经验胜率。必须按真实费用、滑点与可执行订单逻辑做样本外验证。

### P2：持仓界面字段不匹配，且没有真实收益闭环

- `src/web/service.rs:506` 原样返回 OKX 的 `instId/pos/avgPx/upl/uplRatio`。
- `static/app.js:973` 的 `renderPositions` 读取 `instrument/direction/size/average_price/unrealized_pnl` 等另一套字段；有仓位时可能显示空价格、空盈亏，方向默认成多。
- `src/web/service.rs:496` 把总权益直接显示为可用权益；有保证金占用时该值不成立。
- 账户接口未提供已平仓收益、成交手续费、资金费或完整权益曲线；开仓审计也未闭环跟踪成交、撤单和最终退出。
- 主动平仓与修改止损的结果只放入最新分析输出，没有进入开仓执行器的同一审计流水，难以完整还原交易生命周期。

建议：建立统一账户 DTO；以成交和账单为准，把决策、订单、成交、持仓和费用关联起来。持仓界面正确显示并不等于策略已有正收益。

## 4. 处理顺序与尚缺数据

1. 处理目录边界、敏感接口访问与统一执行权限检查。
2. 修复余额/风险硬上限、保护单修改和账户读取失败的行为。
3. 修复 AlphaPilot 决策字段，并完善持仓管理；修复字段会让原来被拒绝的开仓信号开始进入下单流程，应先在模拟环境验证整个链路。
4. 分离信号有效期与挂单寿命，修正账户展示，建立成交和费用记录。
5. 按策略、品种、版本分别回放与样本外测试，再决定是否调整止损、频率和信号阈值。

真实绩效分析仍需要：指定时间段的已平仓记录、订单成交明细（成交时间/价格/数量/手续费）、资金费、入出金与权益序列，以及部署版本/配置变更时间。应计算净胜率、平均净盈亏、利润因子、最大回撤、持仓时间、止损与主动离场占比，分别按 XAU/ETH 等品种和实际策略归因。

在这些数据到位之前，不能用当前余额推断总亏损，不能用提交数推断交易次数，也不能把模型输出的“60% 胜率”当作实际统计。
